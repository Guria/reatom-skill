# v1001 delta vs v1000

Use this file when the project version matters, when migrating from v1000.x to v1001.x, or when a prompt mentions v1001. The goal is to avoid silently using APIs that appeared in v1001 in a v1000 project.

## Rule of thumb

- Check `package.json` / lockfile first.
- If installed packages are `1000.x`, avoid v1001-only APIs unless upgrading.
- The only version-gating is the API surface: `computed`, `withAbort`, `withAsyncData`, `reatomForm`, and route loaders all exist in v1000. Routing render syntax (`layout` vs `exactRender`), codecs, and `go.relative` are v1001-only.

## Appeared or changed in v1001

| Area | v1001 behavior | v1000 behavior / migration note |
|---|---|---|
| Routing render semantics | Page routes are exact-by-default. Use `layout: true` for route shells that render on partial matches and expose `outlet()`. | No `layout` option. `render` matched partially by default; use `exactRender: true` for exact/page behavior. Migrating old layout routes: add `layout: true`. Migrating old page routes: remove/replace `exactRender: true` with default v1001 behavior. |
| Routing codecs | `params` and `search` may be bidirectional codecs (`{ decode, encode }`) or Zod codecs. `route.go()`/`.path()` accept decoded/output types and encode URL strings. Keep Standard Schema as the default for inbound validation/parsing; use codecs when outbound navigation/path building should accept decoded domain values or URL serialization needs explicit bidirectional rules. | Standard Schema/function validation is available, but not bidirectional route codecs. For v1000, pass URL-string-shaped params to `go()` or manually encode/decode. |
| Relative navigation | `route.go.relative(params?)` merges currently matched parent params, useful for sibling routes. Throws if parent is not matched. | Not available; pass all parent params explicitly to `route.go(...)`. |
| React unmount abort | `reatomComponent` defaults `abortOnUnmount: false`; opt into old behavior with `{ abortOnUnmount: true }`. This improves React StrictMode/remount behavior. | Component unmount aborts the render context; StrictMode can cause `AbortError: Component unmount`. Disable StrictMode or use `clearStack()` workaround. |
| Action subscriptions | `action.subscribe((payload, params) => {})`; no initial `[]` call; each action call is delivered as `(payload, params)` in the effect queue. | Callback receives the action call history array, often initially `[]`: `subscribe((calls) => ...)`. |
| Middleware pipeline | `withMiddleware(cb, place)` where `place` is `'invalidation'` (default), `'read'`, or `'computed'`. The target is recompiled after adding middleware. | `withMiddleware(cb, { reactive?: true })`; `{ reactive: true }` is the closest old equivalent for reactive/computed placement. |
| `reatomObservable` / `withObservable` | Producer object API: `{ initState?, getState?, next?, subscribe? }` or `(trigger) => producer`. `getState` pulls current external state; `next` pushes atom writes back; `subscribe` connects lazily. | Older API was `(set) => unsubscribe` plus optional init argument. Update integrations when migrating. |
| Transactions | `withTransaction({ shouldRollback })` filters which errors trigger rollback. | `withTransaction()` rolls back on all non-abort errors. |
| `framePromise` | `framePromise()` always schedules in the `'effect'` queue; no queue argument. | `framePromise(queue?)` accepted a queue argument. Remove the argument for v1001. |
| Utilities | `fromEntries` exported as a type-safe `Object.fromEntries`. | Use `Object.fromEntries` or local typing helper. |
| Primitives | `reatomEnum.set(value)` accepts string values in the type (runtime validation still rejects values outside variants). | Setters were typed only as the enum union; casts were often needed for raw event strings. |
| Types/fixes | Better optional action parameter inference, action subscription tests helper overloads, route child typings. | Mostly internal/type improvements; not usually migration blockers. |

## Important v1001 fixes / behavior hardening

These are usually not APIs to call, but they explain why an upgrade may change edge-case behavior:

- Core recursion and cyclic dependency handling was hardened, including dependencies that update during reads, nested reads, memo chains, multiple subscriptions, and action subscription behavior.
- Subscription callbacks now run outside reactive tracking where appropriate, reducing accidental dependency capture.
- Routing got security hardening; path segments use encode/decode behavior rather than parse/serialize assumptions, and params callbacks inherit search params more correctly.
- Form submit handling includes status correctly.
- `withSuspense` handles init rejection; stale async controllers can be aborted explicitly.
- `abortVar.find` works without a callback.
- Persistence checks `BroadcastChannel` availability more safely.

## Small migration snippets

### Route layout migration

```ts
// v1000 layout/wrapper route
const appRoute = reatomRoute({
  render: ({ outlet }) => html`<main>${outlet()}</main>`,
})

// v1001+
const appRoute = reatomRoute({
  layout: true,
  render: ({ outlet }) => html`<main>${outlet()}</main>`,
})
```

```ts
// v1000 exact/page route
const usersRoute = appRoute.reatomRoute({
  path: 'users',
  exactRender: true,
  render: () => html`Users`,
})

// v1001+ page route (default exact rendering)
const usersRoute = appRoute.reatomRoute({
  path: 'users',
  render: () => html`Users`,
})
```

### Action subscription migration

```ts
// v1000
submit.subscribe((calls) => {
  for (const { payload, params } of calls) log(payload, params)
})

// v1001+
submit.subscribe((payload, params) => {
  log(payload, params)
})
```

### Observable migration

```ts
// v1000
const value = reatomObservable<number>((set) => external.subscribe(set), 0, 'value')

// v1001+
const value = reatomObservable<number>({
  initState: 0,
  subscribe: (set) => external.subscribe(set),
}, 'value')
```
